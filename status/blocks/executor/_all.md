## Реализовано
`harness/pipelines.py` (скриптовые конвейеры math, data_analysis, search, coding: 1–2 вызова модели вместо агента), реестр промптов `profiles/prompts.json` (`HARNESS_VARIANT_<ТИП>=v1|…`), `executor.EXECUTORS` (конвейер, tool-агент), выбор модели по типу (`HARNESS_FORCE_MODEL` только для лабораторий).

## Измерено
`baseline0` (as_is, 100 задач, 3 повтора, без жёсткого бюджета): точность 0,757; очки по типам coding 68,7, data_analysis 53,0, math 61,0, search 43,7; токенов на задачу 639. Потери очков на неверных ответах (грубый потолок = очки/точность − очки): search ≈30,7, data_analysis ≈26,5, math ≈16,5, coding ≈0,9.

## Чем ограничено измерение
Открытые датасеты; конвейер сравнивался на 36–40 задачах по 2–3 повтора; `baseline0` — 25 задач на тип.

## Не проверено
Как меняется точность на задачах организаторов; роль модели (reason против noreason) на 100k и 30k.

## Потенциал
Самый крупный резерв очков по типам — в search и data_analysis (потолок потерь 31 и 27 очков на прогон из ≈226), но достичь нельзя целиком; оценка прироста от конкретной правки есть только на уровне типа (см. ячейки).

## Связи с другими блоками
Принимает ответ решателя, группы батчера; отдаёт ответ верификатору; вызывается под цензором и бюджетом; запасной агент — отдельный блок `fallback`.
